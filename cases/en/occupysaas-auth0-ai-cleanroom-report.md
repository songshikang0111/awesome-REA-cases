# zeroauthy: OccupySaaS's Auth0-compatible identity server, with full replacement still a goal

Category: Applications and clients · Other AI-assisted work
Record date: 2026-11-03
Stage: In progress

At 09:14 Beijing time on November 3, 2026, an English post says laid-off engineers formed OccupySaaS to build AI-assisted clean-room replacements for Auth0 and Salesforce, under Apache-2.0 and with drop-in compatibility. This record covers only Auth0 identity services. Employment history, AI's work share and the motive of replacing former employers come from the post and were not independently established.

The occupysaas organization identifies the zeroauthy repository. Its README was read at commit 5d1c30c1ac7c90d88307c1958af7d7fd20ef0d54, dated November 2 at 14:56 Beijing time, before the window. It describes a self-hostable Auth0 Authentication/Management API implementation from public documentation and open standards, listing discovery/JWKS, authorization code with PKCE, refresh tokens, a console, organizations and event streams. The project reports testing bounded paths with auth0-spa-js, auth0-react, nextjs-auth0 and auth0-cli.

The README claims OpenID Foundation certification for the Basic, Config and Form Post OP profiles, approved October 30; the certification directory was not separately checked here. Even confirmed profile certification would not establish all Auth0 features. The project remains early, with MFA, passwordless/phone flows, more enterprise protocols and production hardening on the roadmap, and exclusions in migration support. AI attribution comes from the candidate; features and tests come from the project, neither constituting independent reproduction. No build, login or real identity credentials were used here. Apache-2.0 is a project declaration, not a legal finding on clean-room compliance.
