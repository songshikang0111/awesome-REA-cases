# An Android privacy-reduced build idea: Sad HAM Society proposes REA static analysis plus proxied traffic

Category: Applications and clients · REA
Record date: 2026-11-24
Stage: Needs verification

At 23:22:12 Beijing time on November 24, 2026, Sad HAM Society (@Sad_HAMs_) proposes a concrete Android-app privacy-research workflow: connect Claude Code to a phone with debugging enabled, obtain an app of interest, use REA to decompile it and list transmitted data and destinations, then proxy actual communication and compare the same questions. The purpose is to distinguish potential transmission paths in static code from runtime observations, not to claim a completed privacy audit of a particular app.

The author further suggests recompiling, renaming and removing unwanted data collection before reinstalling it. No app name, source, model version, packet capture, certificate setup, patch or installation verification is supplied. Complete traffic visibility, complete removal of privacy-invasive logic and passage through signature or integrity checks are not established. Supplementary retrieval confirms attribution. Debugging, proxying and recompilation were not performed here; this proposal is not presented as a universally workable tutorial or an authorization determination.
