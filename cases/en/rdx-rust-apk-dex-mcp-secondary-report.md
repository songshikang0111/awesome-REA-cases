# RDX: Dopax describes a native Rust APK/DEX decompiler with desktop and MCP access

Category: Applications and clients · REA use unconfirmed
Record date: 2026-11-02
Stage: Related project

At 09:24:17 Beijing time on November 2, 2026, Dopax (@tensorstaff) describes RDX as a native Rust APK/DEX desktop decompiler started in September, with MCP support, manifest-to-reconstructed-Java navigation and call tracking without a JVM or external decompilation service. Its purpose is integrating Android package research and navigation into desktop and agent workflows.

After original-post lookup, a name search found Ch0pin/rdx. Its README was read at 4e5a6576c8999acd4b9a88b7bd363267a07227d3, committed October 31 at 19:50:21 Beijing time: earlier supplementary documentation. It describes AI browsing of classes, Java or DEX, manifests and resources through local MCP, with projects separated across multiple instances, and APK/XAPK/APKS/DEX support. Status is alpha: Java reconstruction is still expanding and unsupported methods remain labelled DEX disassembly. The README states Apache-2.0 and credits adaptations of JADX algorithms; this is not a from-scratch implementation without prior decompilation knowledge.
