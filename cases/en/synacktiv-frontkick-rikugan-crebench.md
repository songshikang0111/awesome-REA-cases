# Frontkick and Rikugan: a prompt confound in old crypto tasks and the Rikugan 2.0 rewrite report

Category: Algorithms and feature recovery · Other AI-assisted work
Record date: 2026-11-27
Stage: Analysis test

At 00:17 Beijing time on October 18, 2026, @MalwareBibleJP discusses Synacktiv's Frontkick/Rikugan comparison. Earlier supplementary reading checked Matthieu Breuil's October 13 original for experimental evidence, not as a new publication. The task is to identify algorithms and keys in stripped cryptographic binaries, reimplement decryption and retrieve a flag. The author selects AES-128-CBC and ChaCha20 from CREBench, using hardcode_plain and O0, with Claude 5.5 Sonnet, four runs per task per tool and a cumulative input/output budget of one million tokens. This is not a full-benchmark evaluation.

Rikugan in that old experiment uses predefined tools and argument validation. Frontkick executes generated code directly in Binary Ninja's Python environment without per-action schema validation. It supplies installed libraries and open-binary information in the initial prompt, truncates turns older than the latest four to 500 characters, compacts history at context saturation and retrieves project-validated Python recipes generated by Opus 5.5 after execution errors. The article acknowledges that frequent truncation harms prompt caching and plans improvements; it provides no Frontkick download location.

The article broadly claims about half the tokens and nearly triple the score. Earlier calculations from its eight-run table give a total-token ratio of approximately 0.634 and mean scores of 85.9375/100 versus 31.25/100, not three times as many successful runs. Frontkick's first AES run still consumes 1,007,262 tokens and 42 turns for a zero score; six of Rikugan's eight runs exceed one million tokens, so the budget is not an unexceeded hard guarantee. Rikugan repeatedly tries the unavailable pycryptodome rather than installed cryptography, whereas Frontkick uses the latter with explicit library guidance. Synacktiv therefore does not establish intrinsic CodeAct superiority and recommends aligning library prompts before a rematch. These are the author's published experiments and this collection's earlier table calculations, not independent reruns or guarantees for real software and other models.

At 06:16:03 Beijing time on November 27, 2026, Buzzer (@buzz3r_) announces Rikugan 2.0, describing a complete C++ rewrite with an omc/libomc backend and explaining that OMP was rewritten in C. Binary Ninja and IDA are supported. The author says users can connect existing Claude, ChatGPT, Gemini or Copilot subscriptions, an API key or local inference. This is a version and connectivity release report; faster than before has no quantified benchmark. This collection confirmed the original post, attribution and a video attachment, not the shortened documentation/release links, plugin execution or login integrations. The new post does not rerun the CREBench tasks above: the old gap is not a result for 2.0, and a rewrite does not establish removal of the old prompt confound.
