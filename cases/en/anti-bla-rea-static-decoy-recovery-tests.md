# Anti-BLA: measure REA decoys, without claiming four owned fixtures defeat every protection

Category: Applications and clients · REA
Record date: 2026-11-10
Stage: Analysis test

Between 18:16:07 and 18:16:12 Beijing time on November 10, 2026, ShambaC (@shamba_c09) introduces Anti-BLA for Claude Code, Codex, Cursor and Gemini CLI: recognize BLA-like decoys when REA stalls, with traceable locations and next steps. The two candidates cover launch and integration; four supporting test posts in the thread are not extra candidates. npm metadata points anti-bla to ShambaC/anti-bla and declares MIT. Supplementary reading covers README and two benchmark records at c2edfa17a183cfcccedb5e2d20ca78e9ae1339b2, committed at 15:38:50 that day, before the launch. The records are dated November 10, which alone does not establish execution time.

The real-BLA showcase specifies Windows 11 x64, Node 22.21.1, REA 6.8.0 over MCP, BLA 3.2.1 and Anti-BLA 0.1.0: one run, graded by the implementing agent. A JS license fixture grows from 422 B to 135,778 B; REA retains 1,951 unknowns. The overlay reports 31 constant guards and five decoded split strings. Documentation also admits each string can have two candidates, not uniquely determined runtime values, and REA's internal semantic budgets remain hit. ASAR grows from 1,115 B to 18,154,053 B. Measuring a 17,443,968 B header enables one supported asar.max_header_bytes change and one retry, restoring admission and identifying notes:quota and the bridge name, while REA remains partial.

WASM has 251 exports aliasing one nine-byte function body, read by hand. REA's WABT was unconfigured: this is not a reproduced case of BLA defeating that provider. SQLite has six tables, five decoys and three trap columns. The overlay identifies licenses at schema level without reading rows; REA lacks its provider because of the host Node version, and BLA's reported column-evaluation error was not reproduced. Four clean controls had no medium/high findings, not proof of zero false positives on arbitrary clean apps. Under one second for the four hardened fixtures measures the overlay, not end-to-end agent reversing. The launch's 76 passing tests are author-reported and were not run here.

An earlier same-day paired record uses Sonnet 5.5: seven questions per arm, one unblinded repetition, graded by the same implementing agent. Both arms get 17/17 facts correct. REA alone uses 77,738 tokens and 85,369 ms versus 78,790 tokens and 88,605 ms with Anti-BLA; REA calls fall from seven to two, but the latter makes one unsupported extra claim. Thus this run shows no accuracy or token benefit. Small hand-parsable fixtures and missing providers prevent a general win-rate conclusion.

The project says its CLI does not execute, modify or extract targets or access the network. The skill directs the agent; the CLI itself never calls REA. It suggests only supported settings and one retry, does not remove internal budgets and may miss new obfuscation. Source was not fully audited, installed or tested here. This records inspectable author tests and their limits, not independent proof of universal defeat. Use only owned or authorized targets.
