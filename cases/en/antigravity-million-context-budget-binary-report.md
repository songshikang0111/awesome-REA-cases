# Antigravity context budgets: an older 256k compaction account and a new report of a 512K threshold

Category: Applications and clients · REA use unconfirmed
Record date: 2026-11-16
Stage: Needs verification

A roundup at 09:59:57 Beijing time on November 4, 2026 cites a same-day 00:43 post and GitHub issue #1245. It says Antigravity's CLI shows 1M but the model side often compacts near 256k, losing cache and symbol context. It lists default, 512k and 900k UI tiers with approximately 1.0/1.3/1.8 multipliers and mentions binary allowlist restrictions and harness-unlocking ideas. The use is understanding an agent harness's effective context budget, not confirming a model's native window.

A new candidate at 10:08:13 on November 16 says Varun Mohan announced doubled Antigravity windows for Argon, Carbon and Hydrogen, with automatic compaction per turn described as '3.5 times less.' It looks back to purported community binary research from the previous week, claiming none of 15,575 calls exceeded 300K and median compaction time was 70 seconds, then says community testing now finds a 512K threshold. This is an updated secondary account of the same target: 256k remains an older report, not a fixed current threshold, while 512K cannot be generalized to every version, account or model. The original '3.5 times less' wording is retained rather than converted into a verified savings percentage.

The original announcement, issue repository, pinned version, binary symbols, analysis code, call logs and test conditions were not obtained. There is no independent evidence that the 15,575 calls and the November 4 analysis come from the same researcher. Figures, cache-loss claims and unlocking ideas remain attributed, not proof of bypassed restrictions, lossless context retention or a measured task-speed improvement. Model and REA participation in the analysis remain unknown: an AI-product target does not establish AI-assisted research. No program, account or global configuration was changed here. Status remains unverified.
