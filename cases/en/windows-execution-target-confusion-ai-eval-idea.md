# Click A, execute B: an AI behavior-analysis and repair-regression evaluation idea based on 20 Windows flaws

Category: Algorithms and feature recovery · Other AI-assisted work
Record date: 2026-11-18
Stage: Related project

At 17:29:49 Beijing time on November 18, 2026, a team post describes a public note circulated in its data group on October 21. It argues for training and evaluating model security judgment separately: predicting dangerous behavior, assessing input trust, finding vulnerabilities and verifying repairs. The team says it had organized 20 Windows vulnerabilities, illustrating execution-target confusion where a user clicks A but software executes B through fallback handling in a process-launch interface.

The concrete idea is to supply operation records and program-behavior evidence, then check whether a model locates the target change, explains the trigger and verifies a repair without breaking legitimate behavior. The team also proposes scoping binary, web-security, reversing and 0-day-style tasks by difficulty, environment and grader rather than selling exploits or answer dumps. This is evidence-based AI evaluation design, not publication of all the flaws or reproduced attacks.

October 21 dates the cited note, not this candidate; that note was not separately obtained. The post explicitly disclaims a live leaderboard or current scores for named models. No CVEs, samples, environments, graders, passing reference implementation or repair diffs are supplied. No code or original vulnerabilities were reviewed, nor tasks run here. Twenty is the team's collection count, not twenty successful AI discoveries. Permissions, sandboxes and auditing cannot be replaced by model judgment. REA is unmentioned; retained as a related evaluation idea.
