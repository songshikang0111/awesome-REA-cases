# An AI-native OS idea: Dax proposes reversing system apps and connecting them to an agent

Category: Applications and clients · REA use unconfirmed
Record date: 2026-11-05
Stage: Needs verification

At 03:59:08 Beijing time on November 5, 2026, Dax (@paradax) proposes reverse-engineering all system apps and connecting them to an agent to obtain a genuinely AI-native OS. The direction is agent-callable capabilities for existing system apps rather than only simulated human interaction. This original source is retained, not counted as a new candidate in the later window.

A new candidate at 04:04:17 repeats the architectural idea and adds a scenario: connect Amap's API and use weekday traffic and travel time to a specified building to decide when someone starting work at 10 a.m. should wake up, allowing another 20 minutes to wash and leave. Retrieving the original confirms that the later post is also by Dax (@paradax). Calling a map API does not itself reverse-engineer a map app, and the wake-up schedule remains a desired use, not deployed automation.

Operating system, app inventory, invocation protocol, permissions, state synchronization, model, code and accepted demonstration are absent. The attached image was not inspected and its platform is not guessed. Whether AI or REA performs the reversing is unspecified, so attribution is unknown. Kept as an architectural idea, not recovered interfaces for all system apps, an autonomous operating system, a replaced kernel or acquired privileges. No apps, accounts or devices were operated here.
