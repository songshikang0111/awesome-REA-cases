# Coway Airmega IconS off-cloud: secondary accounts of HTTP root certificates, AI Bluetooth research and a Web Bluetooth installer

Category: Hardware and interoperability · Other AI-assisted work
Record date: 2026-11-14
Stage: Needs verification

At 01:32:44 Beijing time on November 14, 2026, a post relays off-cloud research on a Coway IoCare air purifier, motivated by official-cloud outages, app rewrites and account bans. It says setup downloads Amazon's root CA over plain HTTP. The owner reportedly isolates the device with a Raspberry Pi, observes traffic with mitmproxy and substitutes a trust root so the device accepts a different MQTT endpoint and Home Assistant can communicate directly. MQTT is a device-messaging protocol. This is an account of recovering local interoperability for an owned device, not a vulnerability discovered by this collection.

The earlier post also says Bluetooth setup sends Wi-Fi credentials and cloud configuration in encrypted protobuf, and an AI combined Android logs and decompiled app code into a protocol in about 20 minutes. A new candidate at 09:00:02 on November 14 relays the same research, naming Coway Airmega IconS, Android Bluetooth debug logs and an AI coding agent, and saying the setup payload directly specifies certificate-server URLs. It also describes an open-source Chrome Web Bluetooth installer that pairs the purifier directly to local Home Assistant without soldering or the vendor cloud. Model identification, payload content and browser installation are additional secondary evidence, not hardware acceptance testing by this collection.
