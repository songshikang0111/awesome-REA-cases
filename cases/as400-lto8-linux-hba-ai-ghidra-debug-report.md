# LTO8迁移与Linux HBA：作者称AI加Ghidra修复磁带设备内核崩溃

分类：硬件与设备互通 · 其他 AI 逆向
记录日期：2026-11-23
阶段：待验证

2026年11月23日02:57:05（北京时间），@desitechsuppoat解释磁带驱动研究背景：与主要使用IBM AS/400的客户交换LTO8磁带迁移数据，约100TB且多为扫描图像；旧独立驱动器难找替换件，机架带库不能直接替代其迁移环节，需要出借自有设备。作者称修改AS/400以接受自己的非原厂驱动器，并修补Linux中不完整的HBA（主机总线适配器）模块与模块初始化后的磁带配置。

作者以AI查缺口，在Emacs写C原型／伪代码和注释，自己保留模型不知道的设备操作码、加载与调用顺序，再让Agent生成周边逻辑、测试迭代、请求人工批准，称经过5轮才适应工作方式。补取全文补全结果：驱动器可在弹出后重载，电源断开无法模拟，所以用智能插座让Claude测真实断电／上电及HBA行为，称测试两整天。上月曾因CCB（命令控制块）问题造成至少100次内核陷阱，最后一个问题上周结合AI辅助内核调试和Ghidra找到并修复。

这些是作者回顾，不是本帖内同时发生的可核工时；5轮不是五个独立项目，100TB也不是已验证吞吐量。没有设备型号、内核版本、补丁、Ghidra分析、状态转换矩阵或测试日志，不能确认全部驱动器兼容、不再需要厂商支持或全流程可靠。保留unverified的旧设备互通与调试报告，不复述无关歧视言论。本合集未操作插座、内核或磁带设备，REA未提。
