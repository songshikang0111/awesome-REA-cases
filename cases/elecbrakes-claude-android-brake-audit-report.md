# Elecbrakes拖车制动：Claude读安卓字节码，研究者实测认证缺口并协调修补

分类：硬件与设备互通 · 其他 AI 逆向
记录日期：2026-11-23
阶段：待验证

2026年11月23日20:36:56（北京时间），候选介绍Elecbrakes拖车制动控制器的Claude辅助研究。补读Element Digital于11月19日发表的Patrick Forck与Jeremy McCarthy原文：自有遥控器意外连接陌生拖车后，两人调查安全边界；他们不熟悉安卓Smali字节码，把反编译的com.ElecBrake.Remote交Claude分析BLE特征、命令与认证。作者报告找出四个服务的47个特征，而App只显示42个，制动控制缺少认证。Jeremy另借Claude构建Chrome Web Bluetooth研究工具和未实际用于测试的安卓工具，后续设备实验据作者约四小时；这不是整个研究、工具开发或披露只花四小时。

作者声明只在自有设备、私有道路或封闭环境测试，报告制动变化与状态反馈。固件研究仅为静态检查：他们发现可见更新层用CRC而非签名，但未取得独立bootloader区域、没有刷改恶意固件，因此不能说已验证持久植入。原文还更正了对已修固件更新入口的初次判断：设备会要求已认证绑定连接，未来签名方案仍是厂商计划。此处不提供制动载荷、UUID或操作步骤。

原文时间线为2月初始逆向、5月设备测试，5月18日通知厂商、7月6日发布EB2 3.0.4.4.3与VM1 1.3.4.2.1修复，后续协调至11月19日公开。约60%指厂商10月30日报告的每日活跃EB2／VM1用户固件覆盖，不是所有售出控制器或当前比例；旧ELBC 2000截至原文无修复。补查CVE-2026-96805公开登记，状态PUBLISHED，登记发布日期为11月20日18:58:14Z，与作者所述CISA公告11月19日分开；登记确认缺认证、受影响产品及修复版本，并署名两研究者。原文另列重放与更新通道两个CVE，未逐项读取它们的登记。

原文和CVE登记均早于候选窗口，补查仅为追溯而非新增候选；研究者的AI使用、实测和协调过程为第一方报告，登记是漏洞及版本的外部文档佐证，不是本合集复现。未核厂商原通知、原始工具或完整实验日志，也未连接设备、运行控制程序或刷写固件；模型版本和REA未明，保持unverified，具体安全处理应查厂商最新通知。
