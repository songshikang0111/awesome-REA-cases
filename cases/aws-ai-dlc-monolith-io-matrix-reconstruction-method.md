# AWS AI-DLC：从单体共享变量重建规格，用故障注入检查数据流

2026年11月17日14:14:06（北京时间），AWS韩国用户组（@awskrug）分享AI-DLC Reverse Engineering文章。补充读取同日署名Eunhye Jo的AWS韩文技术博客全文，原文仅标日期，未提供发布时间；这是候选指向的方法来源，不是额外候选。AI-DLC指AI-Driven Development Life Cycle。文章针对遗留单体依赖全局变量和共享内存、函数签名无法说明真实输入输出的问题，避免迁到分阶段DTO（数据传输对象）时丢掉折扣率或传入优惠券处理前的旧金额。

示例是作者为文章编写的虚构商城C程序new_order，共10个阶段，不是真实客户生产系统。作者用tree-sitter AST与宏预处理提取读写，形成R／W／RW／WR及条件标记的I/O矩阵，以到达定义分析追踪生产者到消费者；CI预建代码图，Agent经只读、预定义MCP查询取数据流。AI-DLC 2.11.3的io-matrix plugin把它连到需求、服务边界、API契约与测试。Kiro／Claude Code是支持该工作流的工具示例，不表示两者都参与同一次实测；确定性生成器而非LLM生成API契约与部分代码，AI负责需求、设计及服务实现，人负责步骤配置、术语、未解决访问、有效值规则、边界和审批。

文章报告正常To-Be实现通过生成测试。注入‘把优惠券处理前金额交给支付’后，数据流、条件有效值与黄金主测试失败；8个黄金主输入中仅1个优惠券订单暴露差异，PAYMENT.h_amount为遗留23691、To-Be 24691。再删除隐藏的客户折扣率输入，字段完整性、必填、数据库副作用等测试失败，黄金主8例中5例不同；示例响应金额23691对24990、积分236对0。这里是文章展示的故障注入与执行输出，不是本合集运行、普遍检出率或客户迁移成果。

原文明确同图生成契约和测试有共同遗漏风险；另用人工期望表及SQL／外部调用执行记录检查分析器，但后者不覆盖每个变量读写。数组不分索引，运行顺序依赖配置，动态键、间接指针和未分析外部模块需人工解释或扩展分析。结构测试也不能替代计算行为黄金主，黄金主依赖人工选例。已读全文与代码片段，未取得完整可重跑仓库或原始执行日志，未运行解析器、目标、AI或AWS资源；REA未提及，保留related-project的方法演示边界。
